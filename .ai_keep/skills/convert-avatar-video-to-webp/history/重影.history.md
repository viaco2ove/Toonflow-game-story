# 本地视频转 webp 头像 (convert-avatar-video-to-webp) v7.1

## v7.1 临时目录清理静默失败（2026-09-13）

跑生物路径（`墨老_立绘微动.mp4`）时发现 `_tmp_frames_44888_*` 残留在产物目录里（152 项）。

**根因**：`shutil.rmtree(tmp_root, ignore_errors=True)` 包在 `try/except` 里 —— `ignore_errors=True` 会吞掉所有异常，`except` 分支永不触发，删除失败完全静默。Windows 下 rembg 子进程/扫描器瞬时占句柄就会触发。

**修法**：改为 `for attempt in range(4)` 循环 rmtree + `tmp_root.exists()` 检测 + 递增 sleep，四次仍失败才打 `warn`（带残留项数）。

**生物路径验收**（`墨老_立绘微动.mp4`，75 帧 / 15fps / modnet / portrait）：

```
ANMF: 75 帧全部 244x466 子矩形，blend=NO_BLEND，dispose=NONE，512x512 全画布帧 = 0/75
重影: 不透明像素数 48297..52076（ratio 1.078，非单调累积）→ 无拖影
漂移: bbox left 极差 3px、bottom 0px，相邻帧 left 最大跳变 1px → 无漂移
几何: scale=1.0  crop=[130,46,374,512]  paste=(134,46)  mattingSeconds=26.45
```

modnet 的 mask 时序稳定性远优于 u2net（1.078× vs 2.02×），非生物的局部闪烁问题在生物路径上基本不存在。

## v7 前景位置漂移修复：全局统一几何（2026-09-13）

v6 治好重影后，用户实测非生物立绘反馈：“没有重影但是前景对象位置变来变去。”

**根因**：app `convertAvatarVideoToGif.ts` 的 `matteVideoFrame`（L603）对**每一帧**单独调 `normalizeForegroundLayer`，并把 normalize 后的 buffer 写成 matte 帧（L721）。每帧按自己的不透明 bbox 重新裁切 → 缩放 → 居中底对齐，微动视频里主体每帧动几像素，就会：

| bbox 变化 | 后果 |
|---|---|
| 宽高变 → scale 变 | 主体逐帧微缩放（脉动） |
| 中心变 → 重新居中 | 真实位移被拉回，主体反向跳 |
| 底边变 → 底对齐 | 整体上下推 |

mask 本身不稳定时最致命：某帧丢一块 → bbox 突变 → 整个主体重新居中 → 疾飞几十像素。**这是 app 自身的缺陷，v6 “对齐 app” 把它一起抄了过来。**

**修法**（有意偏离 app）：先扫全部 matte 帧取 bbox **并集**，算一次 crop/scale/paste，再用**同一套几何**刷所有帧（含背景首帧）。帧间真实微动保留，但不再整体漂移；且背景与前景几何同源，`libwebp_anim` 差分矩形更小。

**改动清单**（`convert.py`）：

| 位置 | 改动 |
|---|---|
| 新增 `plan_foreground_geometry(bounds)` | 由 bbox 算出固定 `crop`/`size`/`paste`/`scale` |
| 新增 `apply_foreground_geometry(img, geom)` | 用固定几何重建一帧到 512×512 全透明画布 |
| 新增 `plan_global_foreground_geometry(frames)` | 扫所有帧取 bbox 并集 |
| `normalize_foreground_layer` | 降为上两者的薄封装，加 ⚠️ 禁止逐帧使用注释 |
| 新增 step 6.5 `phase: geometry` | matting 后、背景前算一次全局几何并打日志 |
| step 7 / step 8 | 改走统一的 `normalize_one()`，背景与所有前景帧共用同一套几何 |
| 新增 `--normalize-mode {global,per-frame}` | 默认 `global`；`per-frame` 为逐帧模式（等同 app，仅对照） |
| `webp.json` | 新增 `normalizeMode` 与 `foregroundGeometry` |

**实测**（`收徒系统_立绘微动.mp4`，75 帧 / 15fps / u2net / inanimate，`.cache/_ghost_probe/ab_v7.py`）：

```
per-frame（app 原行为）: paste.x 40..181 spread=141   paste.y 21..49 spread=28
                        内容平移 dx spread=83  相邻帧 dx 最大跳变=74
                        内容平移 dy spread= 6  相邻帧 dy 最大跳变= 5
global（v7 产物）    : scale=1.0 固定，paste=(40,18) 固定，所有帧 dx=dy=0
```

同一产物的 ANMF 全部 `blend=NO_BLEND`（dispose 在 NONE/BACKGROUND 间由 libwebp 自行选择）→ v6 的无重影结论在真实非生物样本上也成立。

**覆盖范围**：step 6.5/7/8 在 portrait 与 inanimate 两条路径共用，一处修复同时生效。

**残留问题（不属 v7 范围）**：rembg 逐帧独立推理，mask 时序不稳定 —— 上例不透明像素数 min/max = 35502/71823（2.02×），个别帧丢掉大半个对象，表现为局部闪烁而非整体位移。portrait 可用 `birefnet_rvm` 缓解；inanimate 暂无方案。

## v6 重影根因定案：编码器必须 libwebp_anim（2026-09-13）

**核心**：`-c:v libwebp` → `-c:v libwebp_anim`，去掉 `-preset picture`。这才是重影的唯一根因，v3~v5 全部诊断方向错误。

**根因机制**：Animated WebP 的 ANMF 帧头有 `disposal`(0=NONE/1=BACKGROUND) 与 `blending`(BLEND/NO_BLEND) 两位，规范默认 `disposal=0 + BLEND` → 新帧 alpha=0 的像素不清画布而是露出上一帧 → 拖影。
ffmpeg 两条 webp 动画路径：

- `-c:v libwebp`：`libavformat/webpenc.c` 自己手拼 ANMF，**disposal 硬编码 0**（FFmpeg [ticket #7941](https://trac.ffmpeg.org/ticket/7941) 挂了 7 年，comment:19 指出 `webpenc.c:137` 的 `avio_w8(s->pb, 0)` 应为 `0x1`，至今未合并）→ **必然重影**
- `-c:v libwebp_anim`：交给 libwebp 官方 `WebPAnimEncoder`，逐帧算最小子矩形 + dispose/blend → **不重影**

**实测**（512×512 软边圆平移 12 帧，lossless，统计每帧不透明像素，期望恒为 6036）：

```
libwebp      : ANMF 全是 512x512 @(0,0) blend=BLEND dispose=NONE
               [6036, 8944, 11852, 14760, 17668, 20576, 23484, 26392,
                29300, 32208, 35116, 38024]  ← 逐帧线性累积 = 拖影
libwebp_anim : ANMF 是 88x88 移动子矩形 blend=NO_BLEND dispose=BACKGROUND
               [6036 ×12]                    ← 零残留
```

验证脚本：`.cache/_ghost_probe/probe4.py`（解析 ANMF 帧头 + 统计 alpha）。

**改动清单**（`convert.py`）：

| 项 | 改动 |
|---|---|
| step 9 编码器 | `-c:v libwebp` → `-c:v libwebp_anim`；删除 `-preset picture`；其余逐项对齐 app（`-lossless 1 -quality 90 -compression_level 4 -loop 0 -an -vsync 0`） |
| 启动校验 | 新增 `assert_webp_anim_encoder()`：ffmpeg 缺 `libwebp_anim` 直接报错，禁止静默回退 |
| 撤销 v4 | 删除 alpha 二值化（把发丝软边打成硬锯齿，app 没有） |
| 撤销 v3 C | 删除 `apply_colorkey_edge()` 及其调用（app 语义路径不做任何 alpha 后处理） |
| 对齐 app | `extract_opaque_bounds` 改为 `alpha > 14` 判定 + `ALPHA_CROP_PADDING = 6` 外扩 |

**覆盖范围**：portrait（birefnet / birefnet_rvm / modnet）与 inanimate（u2net / u2netp / isnet-general-use）共用 step 8 normalize + step 9 编码，单点修复即同时覆盖生物与非生物。

**保留的有意差异**：`resize_inside` 仍保留 `1.0` 不放大上限（app 是 `withoutEnlargement: false` 允许放大）。逐帧独立 normalize 时若允许放大，每帧 bbox 抖动会导致主体缩放脉动，故不跟随。

## v5 禁用 rembg alpha_matting（2026-09-13）

rembg 默认 `alpha_matting=True` 会在边缘把像素 RGB 与背景黑色混合，B 通道被压低约 22%、边缘偏黑。加 `alpha_matting=False` 保留原始 RGB。
（此项本身正确、独立于重影，v6 保留。）

## v4 修复重影根因：normalizeForegroundLayer 居中粘贴（2026-09-12）

> ⚠️ 标题里的"重影根因"是误判，真正根因见 v6。居中粘贴本身正确（对齐 app），但同版引入的 **alpha 二值化已在 v6 撤销**。

**核心**：对齐 app `normalizeForegroundLayer` 的居中粘贴逻辑。

**根因**：v3 normalize 用"左/顶对齐"（`paste(resized, (10, 8))`），character 偏左→背景层沿边覆盖→重影。
app 用"水平居中 + 底部垂直对齐"（`left=(512-w)/2, top=512-h`）。

**修复**：
```python
# v3（左对齐）❌
canvas.paste(resized, (FOREGROUND_SIDE_PADDING, FOREGROUND_TOP_PADDING))

# v4（居中对齐）✅ 对齐 app normalizeForegroundLayer
left = max(0, round((AVATAR_STD_SIZE - w2) / 2))
top  = max(0, AVATAR_STD_SIZE - h2 - FOREGROUND_BOTTOM_PADDING)
canvas.paste(resized, (left, top))
```

**同时新增** `normalizeForegroundLayer` 等效函数（extractOpaqueBounds + resizeInside + 居中画布），在 colorkey 之前处理每一帧。

## v3 修复重影（2026-09-12）

> ⚠️ A 正确但定位错（无损是必要条件，不是根因）；B 正确；**C 已在 v6 撤销**。真正根因见 v6。

| 修复 | 问题 | 方案 |
|------|------|------|
| **A. webp 无损编码** | v2 用 `lossless=0 + q=80` 有损压缩，alpha 边缘被压坏，背景色"漏"出形成重影 | 改为 `lossless=1 + quality=90 + compression_level=4`（对齐 app libwebp_anim） |
| **B. 背景用 512 垫边 matte 帧** | v2 对原始分辨率首帧重新抠图，mask 几何与抽帧管线不一致，导致背景人物区域偏移 | 直接复用 `matte_dir/frame_0001.png`（512×512，同管线产出） |
| **C. colorkey 软抠边** | 发丝/轮廓边缘残留的近黑像素（alpha 极低），无损压缩后"渗出"形成重影 | 对 matte 帧加 `colorkey=0x000000:0.08:0.05` 软透明化（对齐 app legacy 路径） |



### 重影根因分析
重影是合成webp 时导致的，上一帧的图像残留到了下一帧导致了图像拖影。

把 75 个 ANMF header 第 16 字节的 bit0 置 1（disposal: NONE → BACKGROUND），像素数据一字节没动，文件大小完全相同（4918048 bytes）。
文件	BACKGROUND 帧	严格解码	忽略 NO_BLEND	忽略 dispose	三模式一致？
A_current	0/75	1.018	1.147 单调累积	1.018	❌
E_dispose_fix	75/75	1.018	1.018	1.018	✅ 完全一致
C_anim_lossy	17/75	1.018	1.027	1.021	❌
APP_real	36/75	0.996	0.999	0.999	❌
E_dispose_fix 是四个里唯一在三种解码策略下采样序列逐个数字都相同的
（[49690, 49546, 50051, 51210, 50485, 51327, 51328, 49764, 50731]），
也就是不管播放器怎么实现，结果都一样。而且它的严格模式结果
与 A 逐位相同 —— 证明这个改动不改变任何正常视觉效果，纯粹是补上兜底清理。
它比 APP 还稳（APP 三模式有 0.996 / 0.999 / 0.999 的细微飘动）。
残影根因：step_foreground 用全局并集几何把主体位置固定住后，
libwebp_anim 在 -lossless 1 下判断"每帧覆写同一个矩形就够了"，
把 disposal 全部省成 NONE，只留 NO_BLEND 一道防线。
遇到不尊重 NO_BLEND 的播放器就必然残影。app 之所以没这问题，
是它 per-frame normalize 导致主体 bbox 逐帧漂移，反而迫使编码器插入了 36 个 BACKGROUND。
为什么不能靠 ffmpeg 参数解决：
libwebp_anim 只暴露 lossless / preset / cr_threshold / cr_size / quality 五个选项，
没有任何方式指定 disposal。所以修法只能是编码完成后对产物打这个 1 字节位补丁。
