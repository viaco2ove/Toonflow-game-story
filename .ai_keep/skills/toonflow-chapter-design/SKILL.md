# Toonflow 章节内容设计技能
目的：给toonflow game 平台使用的章节，不是写小说！这是给用户游玩的ai 故事
特别注意：“### 用户发言” 是为了显式 安排用户发言。 
## 触发条件

当用户说"写章节"、"设计章节"、"章节内容"、"故事创作"或类似意图时，加载此技能。

---

## 参数
### 故事的目录
- 故事名称:如破碎时空(西游孙悟空、龙珠)
	- chapters：章节内容
	- roles： 角色列表
	- STORY.md 故事说明

## 文件格式（JSON + MD 配对）

Toonflow 章节支持两种格式，**JSON 优先于 MD**（见 `src/toonflow/chapters.py` 的 `_find_chapter_files`）：

1. **JSON 格式** `chapter_N.json`：承载结构化元数据
2. **MD 格式** `chapter_N_标题.md`：承载可读正文，**必须与 JSON 配对存在**

两者放在 `chapters/` 目录，同名/同数字前缀时 JSON 覆盖 MD。

[reference](reference)

      - phase_1_苏醒_stage_1_穿越醒来 来源 “### 穿越醒来”

- “## 非事件” 不转换为 phases数据。
#### 特别注意：
- phase（阶段） 必须有stage 数据。也就是 “## 苏醒” 这种二级标题，里面必须有 “### 穿越醒来” 这种三级标题
- stage（步骤） 的数量：一个phase 里面推荐三个stage 不要过多stage.
- 特殊stage：“### 用户发言”，这将会显式编排用户发言

### chapter_N.json 字段表

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| `title` | string | 章节标题，如 "第 1 章：消失的同桌" | ✅ |
| `sort` | int | 章节序号，从 0 开始（0=第1章，1=第2章） | ✅ |
| `openingRole` | string/null | 开场角色，主线填 "旁白"；自由章节填 null | ✅ |
| `openingText` | string/null | 开场白文本；自由章节填 null | ✅ |
| `completionCondition` | string | 成功条件（见「成功条件写法」）；自由章节填空字符串 "" | ✅ |
| `backgroundPrompt` | string | 章节背景图生图提示词（见下方关键规则） | ✅ |
| `content` | string | 章节正文，等于配对 MD 全文（含 `# 标题` 与 `## 非事件`） | ✅ |

### 关键规则（易错！）
- **背景提示词**必须放 JSON 的 `backgroundPrompt`，**MD 禁止写 `## 章节背景图` 块**——否则 md_parser 降级解析会把该标题行残留进 `content`，污染正文。
- **成功条件**必须放 JSON 的 `completionCondition`，**MD 禁止写 `> 成功条件：...` 行**（合格样本的 MD 保持纯净正文）。
- `content` 字段 = 配对 MD 的完整正文（首行即 `# 标题`），两者必须一致。

## 核心概念

### 事件类型

| 事件类型 | 说明 |
|---------|------|
| **章节内容事件** | 系统自动将正文识别为主体事件，推进剧情 |
| **结束条件检查事件** | 根据"成功条件"字段单独生成，判断章节是继续、成功还是失败 |

> 如果不填写成功条件，章节只有"章节内容"事件，不会触发章节判定。

## ai 故事（toonflow game）章节的常用设定
#### 一般只分两个章节
章节1：故事背景，让用户开始沉浸式 了解故事背景。 多次显示设置 ：“### 用户发言的”
章节2：自由章节，用户可以自由发挥，让故事更加丰富多彩。 一般会在非事件里设定 一堆任务标题（任务标题即可，少就是多，尽量多条的标题，单个标题的内容尽量短，反正运行时ai 会补充任务详细的）
####  世界书
其他章节剧情和世界观 等 作为世界书 来影响故事发展

## ⛔ 格式红线（高频违规，写前逐条自查）

历史上反复出错的 7 个点，写章节 md / json 前必须逐条过一遍：

| # | 红线 | 错误示范 | 正确做法 |
|---|------|---------|---------|
| 1 | **禁用 H4（`####`）** | `### 用户发言` 下写 `#### @旁白 根据…` | 用户发言引导写在 `### 用户发言` 下作为**普通文案**，如 `（旁白引导：根据用户对系统的反应继续…）`。规范只有 `##` 阶段 / `###` 事件两级，**没有 H4** |
| 2 | **`##` 阶段名必须唯一** | 一章里 5 个同名 `## 事件` | 每个 `##` 是独立 Phase，必须起区分名（`## 后山日常` / `## 系统警告` / `## 藏经阁`…）。同名阶段系统无法按名推进 |
| 3 | **`### 用户发言` 不得为空** | `### 用户发言` 后直接接下一 `##` | 至少补一句 `（旁白引导：…）` 说明玩家此刻可做什么，把发言权交给玩家 |
| 4 | **非事件用半角冒号** | `## 非事件：任务分类`（全角 `：`） | `## 非事件: 任务分类（…）`（半角 `:` + 空格），与角色状态约束等统一 |
| 5 | **旁白不替用户说话** | `@旁白：我猜你的想法是…`（把用户内心/台词写进旁白） | 旁白只写场景 / NPC 动作 / 氛围；用户的话与决定归到 `### 用户发言`。删掉"我猜你的想法是"这类越界 |
| 6 | **任务分类不用 `---` 分隔** | 各分类间插 `---` 水平线 | 纯列表，分类间空行即可（`---` 偏离范式） |
| 7 | **md 与 json 的 content 必须同步** | 只改 md，json 的 `content` 字段仍停在旧版 | 改完 `chapters/*.md` 后同步更新对应 `chapter_N.json` 的 `content`（首行 `# 标题` 全文一致）。**改章节不影响 worldbook，无需重跑 worldbook-build** |

> 以上红线对**主线章节**与**自由章节**都适用。上传（`toonflow update` 等写服务器操作）仍需用户明确许可，不自动执行。

## 章节内容写作规范

### 格式要求

1. **使用 Markdown 格式**，通过二级标题 `##` 划分不同阶段，里面必须有三级标题 `###`
2. **对白格式**：`@角色名：台词`，旁白同理，例如 `@旁白：乌坦城的风沙停了下来`， 角色名必须与角色列表里的一致。不能写错！
3. **用户代称**：
   - **旁白叙述**统一写"用户"（如 `@旁白：用户猛地睁开眼`），**禁止用"你"**
   - **NPC 台词**中对玩家说话可用"你"（自然对话，如 `@红缥缈：你是何人？`）——这是允许的
4. **每个大阶段至少一次 `### 用户发言`**，把发言权交给玩家；旁白只引导氛围/描述场景/NPC 动作，**绝不替用户做决定、写感受或台词**

理解什么是事件 什么是非事件！

## 工作流程

1. **确定本章目标**：用户在这一章需要完成什么？（主线章节有结局；自由章节无结束条件）
2. **设计开场场景**：用 `## 大阶段` 引入，角色对白用 `@角色名：`，旁白用"用户"代称
3. **设计用户行动**：每个大阶段放 `### 用户发言`，把发言权交给玩家
4. **抽取元数据写 JSON**：生成 `chapter_N.json`，填 `title/sort/openingRole/openingText/completionCondition/backgroundPrompt/content`
   - `completionCondition`：主线写明确结局判断（足够复杂）；自由章节填空 `""`
   - `backgroundPrompt`：背景图生图提示词（不要写进 MD）
   - `content`：等于配对的 MD 全文（首行 `# 标题`，含 `## 非事件` 任务分类）
5. **写配对 MD**：干净正文，**不写** `## 章节背景图` 块、**不写** `> 成功条件` 行
6. **检查格式**：确认 `##` 大阶段 + `### 用户发言` 齐全、旁白用"用户"、NPC 台词可用"你"、JSON 与 MD 的 content 一致
