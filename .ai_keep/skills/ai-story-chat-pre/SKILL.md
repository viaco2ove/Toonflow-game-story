# AI 故事前置设定收集技能（ai_story_chat_pre）

## 触发条件

当用户表达以下意图时加载此技能：
- 想创作/新建一个 AI 故事（"我想写个新故事"、"创建新故事"）
- 想收集或整理故事的设定资料（"帮我整理故事想法"、"收集故事设定"）
- 展示故事资料模板并要求"做成技能"（即本技能）
- 已经填好或部分填好 `reference/故事资料模板.md`，要求据此整理成正式设定

## 目的与边界

本技能处于创作流程的**前置阶段**：把用户脑子里的故事，通过对话式提问，整理成一份**完整、明确、无歧义、可执行**的《故事设定集》文档，作为下一步创建真正的 AI 故事文件夹（`STORY.md`、`roles/`、`chapters/`、`tasks/`）的唯一依据。

**本技能负责：**
- 引导用户逐步提供设定（一次问 1~3 个问题，不要一次抛完）
- 对模糊信息追问澄清（如等级体系、角色关系、结局分支）
- 整理输出结构化的《故事设定集》Markdown 文档（含 JSON 摘要）

**本技能不负责（留给后续步骤）：**
- 编写具体章节正文（那是 `toonflow-chapter-design` 技能的职责）
- 生成角色文件最终 JSON 参数卡、分配角色ID、头像、语音文件
- 生成图片/音频
- 上传到 Toonflow 平台

## 参考模板

收集字段严格对应工作区根目录的 `reference/故事资料模板.md`（11 个板块）。用户已有填好的模板时，直接按其内容整理；否则按下方"收集要点"逐项引导。

---

## 工作流程

### 第 0 步：确认意图
- 若用户还没有故事想法：先陪用户闲聊发散 2~3 轮，捕捉题材、风格、核心点子，再进入结构化收集。
- 若用户已有想法/已填模板：确认后直接进入第 1 步。

### 第 1 步：逐板块收集（对话式）
按下方"收集要点"的板块顺序提问。规则：
- **一次只问 1~3 个问题**，等用户回答后再继续，禁止一次性列出全部 11 个板块。
- 每个板块收完，用一句话复述确认（"世界观我记下了：……"）。
- 用户回答过简时（如"主角很强"），追问具体化："强到什么程度？有没有等级或数值？"
- 用户说"你帮我编"时，可先给出 1 个建议版本让用户确认，而不是凭空自由发挥到底。

### 第 2 步：整理输出《故事设定集》
收集完毕后，按"输出格式"生成完整文档，并保存到：
工作区根目录的 `.cache/chat_pre/<故事名称>/`（若该目录不存在则创建；文档文件命名为 `<故事名称>.md`；若用户有指定目录则遵用户）。

### 第 3 步：确认与移交
- 向用户展示设定集要点，请用户确认或修改。
- 用户确认后，提示下一步：**"确认后即可据此创建 AI 故事文件夹（STORY.md、roles/、chapters/、tasks/）"**，并询问是否继续。
- 若设定仍有明显缺口（如缺少主线章节规划），先补齐再移交，不要带着缺口进入创建步骤。

---

## 收集要点（逐板块）

### 1. 故事基本信息
- **故事名称**：简短好记，建议带题材暗示（例：我的诡异表妹）。最终会用作文件夹名。
- **题材/类型**：都市悬疑、恐怖、西幻、仙侠、科幻、日常……
- **风格基调**：轻松搞笑 / 黑暗压抑 / 热血燃向 / 温馨治愈 / 悬疑烧脑……
- **一句话卖点**：用一句话说清"这个故事最吸引人之处"。

### 2. 世界观
- 时代背景与地域：什么年代？什么地方？
- 力量/规则体系：有没有等级、魔法、斗气、异能、诡异规则？规则是否公开？
- 特殊规则：如"午夜后诡异出现"、"死亡真实"、"禁止说某词"等——越具体越利于生成章节。
- 与现实的差异：玩家一进来就能感知到什么不同？

### 3. 故事简介
- 2~4 句话，交代背景 + 钩子，给玩家看的开场白。
- 必须包含：玩家是什么人、来到哪里、面临什么谜团/危机。

### 4. 核心事件 / 主线大纲
- 3~8 个关键节点，按顺序排列，每个一句话方向（不写细节）。
- 是否有多结局？多结局要在节点中体现分叉点。

### 5. 玩家（用户）设定
- 玩家角色身份、起点等级、目标、可用能力/道具、限制（如"死亡即失败"）。

### 6. 旁白设定
- 描述（职责）+ 音色（例：混合（清朗温润））。角色类型固定为 narrator。

### 7. NPC 角色资料
每个角色收集：角色名、角色类型（npc）、与玩家的关系、等级（含隐藏等级）、性格、性别、年龄、外貌描述（含画风，如"国风3D动画风格，单人全身"）、语音提示词、背景设定 raw_setting、技能/能力、装备、道具、HP/MP、金钱、其他备注。
- 主角 NPC 至少 3~5 个，配角可简化。
- 等级要具体：给出数值或"表面/真实"双层（例：表面 1 级，真实 50 级）。
- 若用户提供的信息不足，明确标注"待补"并在第 3 步确认前补齐。

### 8. 万能角色
- 是否需要"路人甲"式万能角色（可用 `(扮演xxx)` 扮演任意路人）？需要则命名。

### 9. 章节规划
每章收集：章节名、剧情走向、成功条件（写结果判断，越简单明确越好，例："用户完成自我介绍并目击诡异时刻"）、开场角色、开场台词、玩家互动点。
- 主线章节至少规划到能覆盖第 4 步全部节点。
- 成功条件必须是可判定的结果，不是过程描述。

### 10. 任务列表（可选）
- 自由章节可领取的非主线任务，5~50 个。每个：任务名称、描述、推荐等级、可能奖励、触发地点/角色。
- 没有可留空，注明"暂无"。

### 11. 发布状态与特殊说明
- 发布状态：draft（草稿）/ 已发布等。
- 特殊说明：允许查看角色视角、允许聊天分享、血腥程度、年龄分级等。

## 输出格式

《故事设定集》文档结构（Markdown）：

```markdown
# 故事设定集：<故事名称>

## 1. 基本信息
- 名称 / 题材 / 风格 / 一句话卖点

## 2. 世界观
- 时代背景 / 力量体系 / 特殊规则

## 3. 故事简介
（2~4 句话）

## 4. 主线大纲
1. ...
2. ...

## 5. 玩家设定
- ...

## 6. 旁白设定
- 描述 / 音色

## 7. NPC 角色
### <角色名>
- 关系 / 等级 / 性格 / 性别 / 年龄 / 外貌 / 语音 / raw_setting / 技能 / 装备 / 道具 / HP / MP / 金钱 / 其他

## 8. 万能角色
- ...

## 9. 章节规划
### 第 1 章 <章节名>
- 剧情走向 / 成功条件 / 开场角色 / 开场台词 / 玩家互动点

## 10. 任务列表
| 编号 | 名称 | 描述 | 推荐等级 | 可能奖励 | 触发 |

## 11. 发布状态与特殊说明
- ...

## 附录：JSON 摘要
{ "name": "...", "genre": "...", "style": "...", "hook": "...", "worldview": "...", "outline": [...], "player": {...}, "narrator": {...}, "npcs": [...], "chapters": [...], "tasks": [...], "status": "draft", "notes": [...] }
```

> JSON 摘要的字段名与后续创建步骤对接（STORY.md 章节表、角色参数卡、章节文件、任务列表），保持字段名稳定，不要随意改名。

## 检查清单（移交前必须全部满足）

- [ ] 故事名称、题材、风格、卖点已明确
- [ ] 世界观与力量/规则体系已明确
- [ ] 故事简介 2~4 句已写
- [ ] 主线大纲 3~8 个节点已列
- [ ] 玩家设定已明确（身份/等级/目标/能力）
- [ ] 旁白设定已明确
- [ ] 主角 NPC ≥3 个，字段完整，无"待补"
- [ ] 章节规划覆盖全部主线节点，每章含成功条件与玩家互动点
- [ ] 任务列表已确认（有或明确"暂无"）
- [ ] 发布状态与特殊说明已明确
- [ ] 《故事设定集》已保存到 `.cache/chat_pre/<故事名称>/` 并获用户确认

## 常见失败模式（避免）

- ❌ 一次抛出全部问题，用户不堪重负 → 一次 1~3 问
- ❌ 用户说"随便"就自由发挥到底 → 先给建议版让用户确认
- ❌ 设定集带"待补"字段就移交创建 → 先补齐
- ❌ 成功条件写成过程（"跟角色对话"）→ 写成可判定结果（"用户做出选择并说出理由"）
- ❌ 角色等级模糊（"很强"）→ 追问具体数值或双层等级
