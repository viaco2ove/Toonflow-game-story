# Toonflow API 踩坑经验

## 角色上传/更新核心规则

### 1. 排除非角色文件
- `role.list.md` 是角色目录文档，**不是角色文件**，不要上传
- 只处理 `.md` 文件中包含角色参数卡（`raw_setting`字段）的文件

### 2. playerRole vs NPC
- `用户.md` 是 **playerRole**（玩家角色），不在 `settings.roles` 数组里
- playerRole 是独立的 `playerRole` 字段
- NPC 才放在 `settings.roles` 数组中

### 3. 更新逻辑：修改而非追加
- **核心规则**：服务器已有角色 = 修改；服务器没有的角色 = 新增
- **绝对不能**：遍历本地文件，发现服务器没有就添加新条目
- **正确做法**：
  1. 先 `getWorld` 获取完整数据
  2. 在 `settings.roles` 数组中**查找匹配项并更新**
  3. 只有当角色确实不存在时才新增（一般不需要）
  4. 避免重复：`settings.roles = [更新后的角色列表]` 而不是追加

### 4. worldId 必须传递
- `saveWorld` 时必须包含 `worldId`，否则会创建新世界而不是更新现有世界

## 之前犯的错误
- 把 `role.list.md` 当角色上传 → 服务器多了无效角色
- 把 `用户.md` 当NPC上传 → 角色类型错误
- 脚本可能在某些情况下添加新角色而不是更新现有角色 → 导致重复
